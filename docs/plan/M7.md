# M7: Pipelines, JSON/Parquet ingestion, lineage and object storage (release 1.1)

Granular breakdown written before starting, as master plan §29 requires. Decisions follow ADR-005 (execution plane), ADR-008 (declarative labs) and ADR-009 (minimal custom pipeline engine).

## Scope

| Task | Goal | Acceptance criteria |
|---|---|---|
| **M7-T01** Migration 0013 | Tables `pipelines`, `pipeline_runs`, `dataset_lineage`, `storage_containers`, `storage_objects`; job type stays `pipeline_run` | Up/down applied on both databases; composite tenant FKs; no cross-tenant reference possible |
| **M7-T02** JSON and Parquet ingestion | Raw uploads accept `.json` (array or NDJSON) and `.parquet` besides CSV | Content is validated before storage. Parquet needs the `PAR1` magic at both ends. JSON must be UTF-8 starting with `[` or `{`. Profile and ingest use `read_json`/`read_parquet` under the same caps and sandbox. Malicious fixtures are rejected. |
| **M7-T03** Pipeline engine (runner op `pipeline`) | Linear chain of allowlisted nodes compiled to DuckDB SQL | Nodes: `source`, `filter`, `select`, `join`, `aggregate`, `sql`, `quality_check`, `output`. Structured nodes take no free SQL: values are bound and identifiers validated. The `sql` node goes through the SQL Lab sandbox. Per-step status, row counts and durations are reported. Output caps (rows, columns, lakehouse size) apply. |
| **M7-T04** Pipelines API | CRUD of pipeline resources, run (202), runs history, run detail, cancel | The definition is validated by JSON Schema plus semantic rules (422 with node paths). Cancel works for queued and running jobs (the dispatcher kills the runner). Transient failures are retried up to the pipeline's `retries` (0–2); deterministic failures are never retried. |
| **M7-T05** Pipeline UI | Workspace "Pipelines" page: JSON editor with templates, live validation, a rendered step list, run history with per-step status, cancel | Loading, empty and error states; axe clean |
| **M7-T06** Lineage | Edges from ingest (raw → bronze), transforms (tables read by the SELECT) and pipelines (sources → output). `GET /datasets/{id}/lineage` returns upstream and downstream; the dataset explorer has a "Linaje" view. | Edges come from server-side parsing (`json_serialize_sql`), never from the client. Deleted datasets are shown as such. |
| **M7-T07** Object storage | Storage resources hold containers and objects: upload, list, download, delete, metadata, lifecycle policy (delete or archive after N days) applied by the scheduler | Keys are validated as display names; files are stored under generated keys. Downloads are served as attachments with `nosniff`. Quotas count objects. Every route is in the tenant isolation matrix. |
| **M7-T08** Labs LAB-002 and LAB-006 | New metadata checks `container_exists`, `object_exists`, `lifecycle_rule`, `pipeline_run_succeeded`, `pipeline_has_nodes` | For each lab, the reference solution scores the maximum and an empty attempt scores 0 |
| **M7-T09** Hardening | OpenAPI, docs, isolation and CSRF registries, E2E extension, security gate | `composer check`, pytest, `npm run e2e` green; gate PASS |

## Non-goals (later releases)

- **Pipeline graphs:** branching, a scheduler (cron triggers) and a drag-and-drop builder. Pipelines stay linear and run on demand.
- **Lineage graph UI:** the lineage view is a list (master plan "Future").
- **S3/MinIO backend:** the object store is the local storage driver behind the same interface.

## Risks

| Risk | Mitigation |
|---|---|
| A structured node smuggles SQL | Identifiers must match `^[a-z_][a-z0-9_]*$` and are quoted. Values are bound parameters. Operators and functions come from allowlists. The `sql` node is validated by the SQL Lab sandbox. |
| A malicious Parquet or JSON file | Magic-byte and UTF-8 checks in PHP. The DuckDB readers run in the runner sandbox with OS memory caps and row/column caps. |
| Object storage used for malware or file hosting | No public URLs; downloads only for authorised members, as attachments with `nosniff`; size and quota caps; allowlisted extensions |
| Pipeline runs monopolising the dispatcher | Per-user active job quota, a per-run timeout, cancellation, and retries limited to transient errors |
