# M9: Warehouse, semantic model and dashboards (release 1.2)

Granular breakdown written before starting, as master plan §29 requires. Decisions follow ADR-005 (execution plane), ADR-006 (DuckDB lakehouse), ADR-008 (declarative labs) and ADR-011 (Chart.js 4 vendored locally, already approved there and in `THIRD_PARTY_NOTICES.md`).

## Concepts

- **Warehouse:** a star schema in the gold layer (facts with surrogate-key foreign keys to dimensions). Students build it with the existing SQL transforms and pipelines. M9 adds a referential-integrity data check and LAB-007.
- **Semantic model:** a resource of type `semantic_model` holding a JSON definition with:
  - one fact table;
  - many-to-one relationships to dimension tables (a star, one hop);
  - measures: an aggregation over a fact column, or a ratio of two measures;
  - dimensions: a dimension-table or fact column, with an optional date grain.

  Students never write the query SQL. The runner compiles each request from the model, binding every value and validating every identifier.
- **Dashboard:** a resource of type `dashboard` bound to one semantic model of the same workspace.
  - Widgets: `kpi`, `bar`, `line` and `table`. Each names measures and an optional dimension.
  - Optional global filters: a date range on a date dimension, and value filters on dimensions.
  - Rendering runs **one** job that executes every widget query (plus the distinct values for filter selectors) and stores the result for 24 h. Charts are drawn client-side with Chart.js and come with an accessible data table.

## Non-goals (later releases)

- Free-form calculated measures (DAX-like expressions), many-to-many relationships, snowflake joins and row-level security.
- Drag-and-drop dashboard layout, sharing dashboards publicly, scheduled refresh.
- SCD type 2 history tooling. LAB-007 teaches SCD type 1, which overwrites attributes in place.

## Risks

| Risk | Mitigation |
|---|---|
| SQL injection through model names or filter values | Model identifiers are validated by schema and again in the runner, and quoted. Measure and dimension names become output aliases only after validation. Every filter value is a bound parameter. Aggregations and grains come from allowlists. |
| Expensive dashboards (many widgets, huge joins) | Max 12 widgets per dashboard, one job per render, a 10 s interrupt per query, a dispatcher timeout, 1,000 rows per widget, and the active-jobs quota. |
| Inaccessible charts | `role="img"` with a summary label, a data table alternative for every chart, and colours that pass contrast in the KPI/table widgets. |
