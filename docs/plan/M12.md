# M12: CI/CD, Linux deployment and release packaging

Breakdown written before starting, as master plan §29 requires. The goal is to turn "works on the development machine" into a reproducible, verified release that a school or university can install on Linux.

**Starting point:**
- Every test so far has run only on Windows/XAMPP: PHP 8.1, MariaDB 10.4.
- ADR-001 and ADR-002 promise PHP 8.2+ and MySQL 8 compatibility, but nobody has verified it.
- `worker/requirements.txt` only carries the Windows wheel hash, so `pip install --require-hashes` fails on Linux today.
- At the time, the repository had **no remote**. CI is therefore defined so that it runs **locally with Docker** (verified here) and, unchanged, in GitHub Actions. Since 2026-10-08 the repository is public under Apache-2.0 (ADR-012).

## Non-goals

- Creating a GitHub (or any) remote, or publishing anything: the user decides. On 2026-10-08 the user chose a public repository under Apache-2.0.
- Continuous deployment: releases are built and installed by an operator, as master plan §23 says ("no auto-deploy").
- Kubernetes manifests, multi-node orchestration (scalability roadmap, later).

## Risks

| Risk | Mitigation |
|---|---|
| Hidden MySQL 8 / PHP 8.3 incompatibilities | That is the point of T02: they are found and fixed now, with tests. |
| CI drift between local and GitHub | One script (`ci/run.sh`) used by both. |
| Supply chain (images, actions, wheels) | Images pinned by digest, actions by SHA, wheels by hash, `composer.lock` committed, audits in CI. |
| Docker group on the notebook host is root-equivalent | Documented. A dedicated worker host or rootless Docker is recommended. Notebooks stay off unless enabled. |
