# M11b: Observability

Breakdown written before starting, as master plan §29 requires. The master plan only lists "M11b: observability", so this document sets the scope.

It builds on what exists:
- JSON-lines logs with redaction and a `request_id`, which is returned as `X-Request-Id` and shown in error dialogs;
- the public `/api/v1/health` (database only);
- the admin monitor (counters, jobs, audit, users).

**Constraints:**
- No new dependencies and no external services (ADR-011).
- Everything is visible only to platform admins.
- Metrics never contain ids, paths, SQL, user data or secrets.

## Questions M11b answers for an operator

1. Is everything running: database, storage, dispatchers, scheduler, mailer, the notebook worker?
2. Is the platform slow or failing, and where (which route, which job type)?
3. A student reports "Error, ID: 01J…": what happened in that request?

## Scope

| Task | Goal | Acceptance criteria |
|---|---|---|
| **M11b-T01** Migration 0019 | `request_metrics`: per minute × route name × method × status class, with count, total and max ms, and a fixed latency histogram (≤50, 100, 250, 500, 1000, 2500, 5000 ms, +Inf). `component_heartbeats`: component, instance, last_seen_at and safe details. | Up/down on both DBs. Platform tables (not tenant-owned). Portable upsert (`INSERT … ON DUPLICATE KEY UPDATE`). |
| **M11b-T02** Request metrics | The Kernel times every request and records it under the **route name** (never the URL). Unmatched paths use `_unmatched` and static assets are not recorded. Requests above `observability.slow_request_ms` (2,000) log a `slow_request` warning. | Recording failures never break a response (they are caught and logged once). Ids in URLs never reach the table. Recording can be disabled by config. |
| **M11b-T03** Heartbeats | The dispatcher (main and `--notebooks`), the mailer and the scheduler upsert a heartbeat, throttled to every 15 s. The notebook worker reports whether Docker is available. The scheduler reports its last result summary. | Details are allowlisted (counts and booleans only). Heartbeat failures never stop a worker. |
| **M11b-T04** Admin health | `GET /api/v1/admin/health` returns per-component status (`ok`, `warning`, `down`, `disabled`) and an overall status. Components: database (latency), storage (writable, free space), job queue (oldest queued age), dispatcher, notebook worker (docker mode only), scheduler, mailer (outbox backlog), Python runner. | The web server never calls the Docker daemon (ADR-010); Docker status comes from the worker heartbeat. No paths or versions are exposed. The public `/health` is unchanged. |
| **M11b-T05** Admin metrics | `GET /api/v1/admin/metrics?window=1h\|24h\|7d`. HTTP: requests, 4xx/5xx rates, p50/p95/p99 from the histograms, slowest and busiest routes, time series. Jobs per type: count, failure rate, queue wait p50/p95, run time p50/p95. | Window from an allowlist (422 otherwise). Percentiles are computed from the histogram (upper bucket bound) and documented as approximations. Job rows are bounded. |
| **M11b-T06** Log lookup | `GET /api/v1/admin/logs?request_id=&level=&since=` reads the last 2 days of app logs. It returns only `ts`, `level`, `event` and `request_id`, never `context`. At most 200 entries. | Filters are validated (ULID-shaped request id, level allowlist). Reads lines up to 64 KB and stops at 20 MB per call. |
| **M11b-T07** Retention | Maintenance purges `request_metrics` older than 14 days and `app-*.log` files older than 30 days (`LOG_RETENTION_DAYS`). | Only files matching `app-YYYY-MM-DD.log` in the log directory are removed. |
| **M11b-T08** UI | Admin page tab **Observabilidad**: component cards, a window selector, KPIs, a Chart.js chart of requests/errors with a data-table alternative, the route and job tables, and a request-id log lookup. | Loading, empty and error states. `.text()` only. Chart `role="img"` with a label. axe clean. |
| **M11b-T09** Hardening | Tests: unit tests for percentiles and the histogram; integration tests for recording (no ids), metrics, health with stale heartbeats, logs without context, retention, 403 for non-admins. OpenAPI, `docs/architecture/OBSERVABILITY.md`, SETUP, E2E, security gate. | `composer check`, pytest and `npm run e2e` green; gate PASS. |

## Non-goals

- Prometheus/OpenTelemetry exporters, external alerting (email/Slack), distributed tracing. A `/metrics` scrape endpoint with a token is a candidate for M12 (deployment).
- Per-user or per-tenant analytics: metrics are deliberately aggregated by route only.

## Risks

| Risk | Mitigation |
|---|---|
| A DB write per request slows requests | One upsert on an indexed key, a few ms; can be disabled (`OBSERVABILITY_REQUEST_METRICS=0`). Measured and recorded in `PERFORMANCE.md`. |
| Metrics leak sensitive data | Keys are route names and status classes only; heartbeat details are allowlisted; logs return no context. |
| Log lookup as a DoS vector | Platform admins only, bounded bytes per call, rate limited like other admin routes. |
